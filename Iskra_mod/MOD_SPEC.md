# Мод «Искра-Симс» — спецификация

Мост между The Sims 4 и Python-сервером мышления (server.py).
Перехватывает управление выбранными симами, отдаёт их «мозг» внешнему LLM-серверу.

## Цель
Заменить штатный ИИ выбранных симов на наш сервер сознания. Сим становится
«телом» для агента Искры: игра даёт восприятие и потребности, сервер возвращает
намерения и реплики, мод исполняет их игровыми командами.

## Технический контекст
- The Sims 4 написан на Python 3.7
- Моды — пропатченные .py, упакованные в .ts4script (zip-архив)
- Используем S4CL (Sims 4 Community Library) для доступа к API и инъекций
- HTTP к серверу через urllib в ОТДЕЛЬНОМ ПОТОКЕ (синхронный запрос заморозит игру)
- Сервер: http://127.0.0.1:8000 (тот же что у Godot-версии)

## Главный принцип: неблокирующий цикл
Игровой тик и мышление НЕ блокируют друг друга (как is_thinking в thinking_bridge.gd):
- Мод каждый тик кладёт снимок восприятия в очередь
- Поток-воркер параллельно дёргает сервер
- Игра берёт ПОСЛЕДНЕЕ готовое намерение, не дожидаясь нового
- Пока сервер думает (3-15 сек), сим продолжает текущее действие

## Архитектура мода

### Модуль 1 — Управление симами (control.py)
- Регистрация: какие симы под управлением Искры (по ID или тегу)
- Глушение штатного ИИ: отключить автономию у выбранных симов
  (autonomy disable, очистка очереди взаимодействий каждый тик)
- Реестр агентов: sim_id → {server_endpoint, last_intention, is_thinking}

### Модуль 2 — Восприятие (perception.py)
Каждый тик собирает снимок для сервера:
- **Потребности** (читаем из commodity tracker сима):
  hunger, energy, bladder, hygiene, social, fun → нормализуем в 0..1
- **Окружение** (что рядом в радиусе):
  объекты (холодильник, кровать, душ, ТВ...), их тип и расстояние
  другие симы рядом → их ID и что они делают
- **Текущее состояние**: где сим, что сейчас делает, настроение (moodlet)
- Формат снимка — как PerceptionSnapshot в server.py, адаптированный:
  vision → список объектов, internal_state → потребности Симс

### Модуль 3 — Действие (action.py)
Переводит intention от сервера в игровые команды:
- goal "eat" → найти холодильник/еду → push interaction "Grab a plate"
- goal "rest" → найти кровать → push interaction "Sleep"
- goal "hygiene" → душ/туалет
- goal "fun" → ТВ, компьютер, объект развлечения
- goal "social" → найти целевого сима → инициировать разговор (см. модуль 4)
- goal "explore/wander" → переместиться в другую комнату
- goal "none" → стоять, ждать
- Поиск объектов: по типу через game object manager, ближайший подходящий

### Модуль 4 — Общение (social.py)
КЛЮЧЕВОЙ и самый сложный модуль. Связывает игровую механику с реальным диалогом.
- Когда сим А инициирует social с симом Б:
  1. В игре проигрывается анимация разговора (штатная)
  2. На сервер уходит сигнал «А обращается к Б» — попадает в восприятие Б
  3. Сервер ведёт РЕАЛЬНЫЙ обмен репликами между LLM А и Б (2-4 хода)
  4. Реплики показываются субтитрами над симами
  5. Сервер оценивает тон разговора → возвращает корректировку social
  6. Мод применяет: social_A += X, social_B += Y (зависит от тона!)
     тёплый разговор → +много, конфликт → +мало или минус
- Темп: диалог идёт «в рассрочку», по реплике за тик, анимация подстроена
- Разговор пишется в LTM обоих от первого лица (на стороне сервера)

### Модуль 5 — Мост (bridge.py)
- Поток-воркер с очередью запросов
- Отправка снимка на POST /think (или /think_social для диалогов)
- Получение intention + utterance
- Эндпоинт для приёма корректировок счётчиков от сервера
- Обработка ошибок: сервер недоступен → сим на штатном автопилоте

## Поток данных (один тик)
```
Игра → perception.py собирает снимок
     → bridge.py кладёт в очередь (неблокирующе)
     → [воркер] POST /think → сервер думает
     → [воркер] получил intention + utterance
     → action.py исполняет последнее готовое намерение
     → если social → social.py ведёт диалог, применяет счётчики
```

## Структура файлов мода
```
iskra_sims/
  __init__.py
  control.py       — управление симами, глушение ИИ
  perception.py    — сбор снимка восприятия
  action.py        — intention → игровые команды
  social.py        — диалоги + синхронизация social-счётчика
  bridge.py        — HTTP-мост, поток-воркер, очередь
  config.py        — endpoint сервера, ID управляемых симов, тайминги
```

## Этапы разработки (по приоритету)
1. **Минимальный мост**: один сим, заглушить ИИ, слать потребности на сервер,
   принимать goal, исполнять одно действие (eat). Проверить что петля работает.
2. **Полное восприятие**: объекты вокруг, другие симы, настроение.
3. **Все базовые действия**: eat, rest, hygiene, fun, wander.
4. **Общение**: диалог между двумя агентами + синхронизация social.
5. **Несколько агентов**: 2-4 сима с разными моделями одновременно.

## Известные риски
- Синхронный HTTP заморозит игру — ВСЁ общение с сервером только через поток
- Темп LLM (секунды) vs темп игры (тики) — диалоги вести «в рассрочку»
- Перехват автономии: игра может возвращать управление, чистить очередь каждый тик
- Анимации Симс жёстко привязаны к interaction'ам — не всякое намерение ляжет гладко

## Связь с server.py
Сервер почти не меняется. Адаптировать:
- PerceptionSnapshot: добавить потребности Симс (bladder, hygiene, social, fun)
- Новый эндпоинт /think_social для диалогового обмена между двумя агентами
- Эндпоинт отдаёт корректировку social-счётчиков по тону разговора
- Цели расширить: добавить hygiene, fun, social к существующим eat/drink/rest/...
